# ADR-0010：不透明トークン前提と入口方式の再評価

- 記録日：2026-10-25
- 状態：利用者が指定した今回の設計前提・再評価の範囲を記録。入口方式・SQS・Outboxの採用決定ではない。

## 今回の前提

利用者から「今はJWTではなく不透明トークンの前提」と指定されたため、現在の構成設計は不透明トークンで進める。JWTとの永久的な優劣を決定したものではない。

不透明トークンはサーバー側Sessionsに照会する案。トークン期限、ハッシュ保存、顧客一括失効、キャッシュなし、残量予約等の具体方式は詳細設計の提案として扱う。

## 入口の再評価

利用者から、適切な構成を判断するためREST案とWeb案の両方の構成図を作成するよう依頼された。REST＋WAF＋EventとCloudFront＋WAF＋Webを、共通の不透明トークン・非同期基盤で比較する。

RESTは設定の簡潔さから暫定推奨。Webは有力候補として検証する。既存Python資産・移植費用を採否理由にしない。安全性・費用・性能・運用の検証完了は確認されていない。

## 過去判断の適用範囲

- ADR-0001のFastAPIはREST案の実装候補として条件付き適用。
- ADR-0005のREST採用、ADR-0008のWeb不採用は、今回の最終判断として扱わない。
- ADR-0006のJWT署名鍵を理由としたSecrets Manager採用は今回の方式には適用しない。他の秘密管理用途は別途判断する。
- ADR-0002のAPI／Worker分離、ADR-0003の永続化・使用量記録、ADR-0004の追加CMK不採用、ADR-0007のJSON出力は継続方針。
- ADR-0009のSQSは検討中。Outbox・配送Lambdaも提案であり、比較図に存在するだけでは採用済みにならない。
