# awsMemo

複数顧客企業のWPFアプリからAmazon Bedrockを利用し、生成JSONを取得する非同期APIの設計・検討記録。

**最新の検討は[docsの入口](docs/README.md)から確認してください。** 更新日：2026-10-28。

## スマホで最初に確認する順番

最初の確認は次の3か所で十分です。図や大きな表は、必要になってから確認できます。

1. **[次の作業](docs/current/次の作業.md)** — まず「1. 業務ルールと合格条件を決める」を読む。「利用者の承認が必要」の箇所が、最初に相談したい内容です。残りの2作業は見出しと成果物だけ確認してください。
2. **[今回のレビュー補足](docs/current/構成設計.md#レビューで補足した設計案)** — 保守キー、停止と署名URL、WPF再起動、成果物、結果不明、品質、受付上限の7点を確認。気になる点だけメモすれば十分です。
3. **[現在の検討状況](docs/current/検討状況.md)** — 決定済みの前提と、まだ提案・未決の内容が意図どおりか確認します。

**返してほしいこと：** 分かる範囲の業務ルールと、気になる点・違和感。未定のものは「未定」で構いません。全項目をその場で承認する必要はありません。

構造変更の候補は[次の作業の「2」](docs/current/次の作業.md#2-状態遷移復旧構造変更案を具体化する)に集約しています。採用構成図・61項目・過去資料は初回確認では後回しで大丈夫です。

## 現在の状態

- 認証は**不透明トークン前提**で設計する。
- 入口は**API Gateway Regional REST API＋WAF＋API Event Functionを採用決定（2026-10-26）**。
- 非同期ジョブ、API／Worker分離、DynamoDB、S3のJSON保存と署名URL配信、WPFポーリングの方針を継続。
- クレジットはトークン量から独自計算し、換算係数・丸め設定をDBで管理する。DBの7テーブル・ER図は設計案。
- SQS Fair Queues、Outbox、入力S3保存、残量予約・精算は提案・検討中。
- AWS環境の構築・デプロイ・負荷試験・費用実測の完了は確認していない。
