# ADR-0004: 請求データ保護に専用のKMSカスタマー管理キーを採用しない

> **現在の適用範囲（2026-10-25）：** 追加CMKを採らず標準暗号化を使う既存判断を継続。契約・要件の変更時に再評価する。 [検討状況](../current/検討状況.md) / [後続ADR-0010](0010_不透明トークン前提と入口方式の再評価.md)。以下は当時の判断記録。

- **決定日**: 2026-10-13
- **当時のステータス**: **不採用（現時点）** — 専用のKMSカスタマー管理キー（customer managed key）を新規導入しない。AWSサービスの既定の保存時暗号化は維持する。
- **対象**: 請求用トークン使用量、DynamoDB、S3、KMS

## 背景・最重要要件

複数企業向けのサービスで、Amazon Bedrockによる入力/出力トークン使用量をDBに保管し、独自単価計算で顧客へ料金を請求する。したがって、**請求根拠データの正確性、完全性、追跡可能性、復旧可能性**が最重要。

検討当初は「請求に使う重要データなのでKMSを追加すべきか」という問題提起があった。

## 決定

**現段階では専用のAWS KMSカスタマー管理キー（CMK）を新規採用しない。**

- DynamoDBは既定の保存時暗号化を利用する。
- S3は既定のSSE-S3で保存時暗号化する。
- 通信時はTLSを利用し、顧客認証・顧客単位の認可を行う。
- 今回の判断は「暗号化しない」ことを意味しない。また、AWS内部でKMSが一切使われないことを保証するものでもない。対象は**追加の顧客管理キーの採用**である。

## 不採用理由

1. **KMSは正当なDynamoDB書き込み権限による改ざんを防げない。** キーの利用を許されたサービス経由の更新は、暗号化の有無にかかわらず成立する。
2. このシステムで一番重要なのは、データ秘匿だけでなく**請求元データの整合性と後日の説明可能性**。
3. 顧客管理キーを設けると、鍵ポリシー管理、権限設定、キー無効化による可用性リスク、KMS関連課金と運用負荷が増える。
4. 現時点で独自鍵の保持・利用履歴・ローテーション等を求める顧客契約または規制要件は提示されていない。

## 代替・優先して採用する対策

| 防ぎたい問題 | 優先する対策 | 状態 |
| --- | --- | --- |
| 既存使用量の不正上書き | IAM最小権限、追記型UsageEvents、§PutItem§の条件付き書き込み | 設計方針 / 具体方式は未確定 |
| 非同期再試行による二重請求 | ジョブ/モデル呼び出しの一意ID、冪等性、集計時の重複排除 | 設計検討中 |
| トークン値の偽装 | クライアント申告を信用せず、Bedrockのサーバー側利用量情報を記録 | 原則採用 |
| 操作が追跡できない | CloudTrailのDynamoDBデータイベント、構造化アプリ監査ログ | 導入計画 |
| 誤操作・データ損失 | DynamoDB PITR（ポイントインタイムリカバリ）、復元手順の定期検証 | 導入計画 |
| 請求紛争で証拠がない | 請求確定時の明細スナップショット、S3 Object Lock等の保全方式 | 検討中 |

**留意点:** DynamoDB PITRは復旧機構であり、単独では長期の改ざん耐性を担保しない。CloudTrailのイベント記録はデータの変更前後の値をそのまま保証するものではない。請求に用いるイベントの証拠保全は別途設計する。

## 比較した案

| 案 | 判断 | 理由 |
| --- | --- | --- |
| **AWSサービスの標準暗号化 + 最小権限・監査・冪等性・PITR** | **今回選択** | 請求の正確性を直接守る対策を優先できる |
| DynamoDB/S3で専用KMSカスタマー管理キーを使用 | **不採用（現時点）** | 詳細な鍵制御のメリットはあるが、主目的の改ざん防止には直接効かない |
| 保存時暗号化を省略 | **不採用** | 情報保護上不適切。サービス標準の暗号化を利用する |

## 再検討条件

- 顧客契約・監査基準・規制要件でカスタマー管理キー、キー操作の監査、鍵の無効化や管理権限分離が求められた場合。
- データの秘匿性・アクセス経路要件が変わり、標準の保存時暗号化では不足する場合。
- 顧客別鍵管理や暗号鍵のライフサイクル統制が求められた場合。

## 判断の経緯

2026-10-13: 課金用トークン実績が最重要と判明。KMSによる保存時暗号化と請求データの改ざん防止は別の論点であると整理し、**追加の顧客管理キーは採用しない**という利用者判断を記録。
