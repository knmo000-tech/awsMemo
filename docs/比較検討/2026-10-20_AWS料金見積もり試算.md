# AWS料金見積もり試算（2026-10-20）

## 目的と共通条件

AWS Pricing Calculatorに入力するための**仮定・算式・入力値**を記録する。金額は東京リージョンのCalculatorで再確認し、無料枠や為替を含む確定請求額とは区別する。

| 条件 | 値 |
| --- | ---: |
| 顧客企業 | 100社 |
| 1社の生成回数 | 50件/営業日 |
| 営業日 | 20日/月 |
| 生成時間 | 120秒/件 |
| ポーリング | 10秒ごと（初回10秒後） |
| 月間ジョブ | **100,000件** |
| ポーリング回数 | **12回/ジョブ** |
| 認証 | 見積もり上は1回/ジョブ（実装ではJWT再利用するため保守的） |
| JSON平均サイズ | **30KB/件**（実態想定10KBに対し3倍） |
| JSON保持期間 | 90日 |
| リージョン | Asia Pacific (Tokyo) |

ジョブ数 = 100社 × 50件 × 20日 = **100,000件/月**。
状態確認 = 120秒 ÷ 10秒 = **12回/ジョブ**。
API呼び出し = 認証1 + 登録1 + 状態確認12 = **14回/ジョブ、140万回/月**。完了後のS3署名URL直接GETはAPI Gateway/WAFのリクエスト数に含めない。SQS待ち・遅延・リトライ・管理画面アクセス等は別途加算。

## DynamoDB（オンデマンド、Standard）

仮の物理設計：Customers 2KB/件、Jobs 2KB/件、UsageEvents 1KB/件。通常の書き込みは1KB単位で切り上げ、結果整合性読み取りは4KB以下で0.5 RRU/回。トランザクション・GSI・リトライなし。

| 1ジョブの処理 | テーブル | 読み取り回数 | 書き込み回数 | RRU | WRU |
| --- | --- | ---: | ---: | ---: | ---: |
| 認証時の顧客参照 | Customers | 1 | 0 | 0.5 | 0 |
| ジョブ作成 | Jobs | 0 | 1 | 0 | 2 |
| 10秒間隔ポーリング | Jobs | 12 | 0 | 6 | 0 |
| Workerによる状態参照 | Jobs | 1 | 0 | 0.5 | 0 |
| 実行中への状態更新 | Jobs | 0 | 1 | 0 | 2 |
| 完了への状態更新 | Jobs | 0 | 1 | 0 | 2 |
| 利用実績記録 | UsageEvents | 0 | 1 | 0 | 1 |
| 請求・集計向け追加参照（仮置き） | UsageEvents等 | 2 | 0 | 1 | 0 |
| **合計/ジョブ** | | **16** | **4** | **8** | **7** |
| **合計/月** | | **1,600,000** | **400,000** | **800,000** | **700,000** |

読み取り：100,000 × (1 + 12 + 1 + 2) = **160万操作/月**、全て4KB以下・結果整合性なら **80万RRU/月**。
書き込み：100,000 × (Jobs 2KB × 3回 + UsageEvents 1KB × 1回) = **70万WRU/月**（操作は40万回）。
**UpdateItemは変更した属性だけでなく、更新前後のアイテム全体サイズの大きい方が課金の基準**。失敗・再試行、条件付き書き込み、GSI追加書き込み等で増える。請求集計の2読み取り/ジョブは実装確定値ではない。

**容量の定常状態**：Customers 100×2KB + Jobs 10万×3か月×2KB + UsageEvents 10万×36か月×1KB ≒ **4.0GB（10進単位）**。GSI・項目オーバーヘッド等の余裕を含め**Calculatorには5GB**を暫定入力。36か月のUsageEventsが蓄積した時点の値であり、初月の容量ではない。保持期間自体は未決定。PITRを採用する場合は別途見積もる。

**Calculator注意**：「操作回数」と「RRU/WRU」は異なる。画面が月間のリクエストユニットを聞くなら **80万RRU・70万WRU**、操作回数とサイズ・整合性を別々に聞くなら **160万読み取り・40万書き込み**を入力し、二重換算しない。

## Amazon S3（生成結果JSON）

S3 Standard、平均30KB、1ジョブ1回PUT、完了後1回GET、90日後にライフサイクル削除する仮定。

| 項目 | 計算 | Calculator向け |
| --- | --- | ---: |
| 月間新規データ | 100,000 × 30KB | **3GB/月** |
| 保持容量（定常状態） | 3GB × 約3か月 | **9GB**（余裕込み10GBでも可） |
| PUT/COPY/POST/LIST | 100,000 × 1回 | **100,000回/月** |
| GET | 100,000 × 1回 | **100,000回/月** |
| S3→インターネット転送 | 100,000 × 30KB | **3GB/月** |
| インターネット→S3 | Worker Lambdaから同一リージョン内で保存 | **0GB/月** |
| リージョン間転送 | なし | **0GB/月** |

GBは10進単位（1GB=10億バイト）。GiB表示なら9GB≈8.38GiB、3GB≈2.79GiB。S3 StandardのGETリクエスト課金とインターネット向けデータ転送は別項目。転送の無料枠適用は他サービスとの合算で確認。S3への署名付きURLの発行そのものはGETではない。失敗ジョブ・再ダウンロード・ライフサイクル移行/削除の条件により実績は変動。

## AWS WAF（API Gateway REST APIにWeb ACLを関連付け）

| 項目 | 入力値 | 説明 |
| --- | ---: | --- |
| Web ACL | **1** | API Gatewayを守る設定一式 |
| Web ACLに直接追加するカスタムルール | **4** | IPレート制限、/authレート制限、不要メソッド拒否、不要パス拒否 |
| 自作ルールグループ | **0** | 自作グループは利用しない |
| 自作グループ内ルール | **0** | 自作グループがないため |
| AWSマネージドルールグループ | **2** | Common Rule Set、Known Bad Inputs（候補） |
| 検査するリクエスト | **1,400,000回/月** | 100,000 × (1認証+1登録+12ポーリング) |
| 余裕を持つ場合 | **1,500,000回/月** | 遅延・リトライ等を考慮した丸め |
| Bot Control / Fraud Control | 無効 | 専用機能を使わない |
| CAPTCHA / Challenge | 0 | デスクトップアプリでは当面利用しない |

**用語**：Web ACL＝ルールをまとめる設定、直接ルール＝ACL直下の検査条件、自作ルールグループ＝自分で複数ルールを束ねる箱、グループ内ルール＝その箱の中身、マネージドルールグループ＝AWS等が提供するルール集。

**基本料金の参考算式**：Web ACL 1×$5 + ルール/ルールグループ相当6×$1 + 140万リクエスト÷100万×$0.60 ≒ **$11.84/月**。これは標準的な単価を用いた**説明用概算**であり、実際のCalculatorでの「直接ルール」「マネージドルールグループ」の課金上の数え方、WCU、本文検査容量、有料マネージドルール、ログ出力、その他オプションを確認すること。**グループ内部のルール数を機械的に加算して二重計上しない**。

## API Gateway REST API

- 月間リクエスト：**140万回**（余裕を持つ場合150万回）。
- ステージキャッシュ：**無効**。認証・ジョブ作成・変化するジョブ状態のAPIにキャッシュを利用しない。キャッシュメモリ容量/稼働時間は0相当。
- REST APIのAPI呼び出し料金、レスポンス転送、WAFは別々に見積もる。
- GET /jobs/{jobId} のレスポンスは小容量を想定。データ転送量を見積もる際は実際の平均レスポンスサイズを別途設定する。

## 見積もり時の重要な未確定事項

1. JWT再利用による実際の認証頻度、初回ポーリングのタイミング、SQS待機を含む実処理時間。
2. DynamoDBのテーブル/インデックス設計、強い整合性の要否、UsageEvents保持年数、PITR。
3. S3の実平均JSONサイズ、保持日数、再ダウンロード率。
4. WAFの実ルール構成、ログ保存、WCU、東京リージョンでのCalculator単価。
5. Bedrockモデル別入力/出力トークン料金、SQS・Lambda・CloudWatch・Secrets Manager等の別途費用。
