# ADR-0007: Bedrock生成物をCSVからJSONに変更する

- **決定日**: 2026-10-15
- **ステータス**: **採用（出力形式のみ変更、実装未確認）**

## 背景
当初の成果物はCSVを想定していたが、生成される成果物の形式が**JSON**に変更された。出力サイズは最大で約1MBを想定する。

## 決定
Bedrock実行結果の成果物を、CSVではなく**JSON**として取り扱う。S3内の成果物の例は `result.json` とし、オブジェクトの `Content-Type` を `application/json` とする。

**変更しない構成**:
- API Lambda (FastAPI + Mangum) とWorker Lambdaの2関数構成
- 非同期Worker Lambda起動とDynamoDBのジョブ状態管理
- WPFクライアントによる `GET /jobs/{jobId}` ポーリング
- Worker Lambdaによる成果物のS3保存
- API Lambdaの認可後の短命な署名付きURL発行と、クライアントからS3への直接ダウンロード
- 既存保守キー照合、JWT、WAF/REST API、監査・最小権限

## 変更理由
- 利用側が必要とする出力形式がJSONになったため。結果を構造化データとして扱える。
- 1MB程度であれば同期応答に載せる案も考えられるが、サイズの小ささだけではBedrockの処理時間や非同期実行の必要性はなくならない。
- 非同期処理とS3を維持することで、ジョブの追跡・再取得・ダウンロード機構を変えずに出力形式だけ移行できる。

## 比較した案と不採用理由
| 案 | 今回の判断 | 理由 |
| --- | --- | --- |
| JSONをS3保存し署名付きURLで取得 | **採用** | 非同期・ポーリングの現行設計を維持 |
| API LambdaからJSONを直接同期返却 | **今回不採用** | 非同期→同期への変更が必要。Bedrock実行時間やタイムアウトを別途評価する必要がある |
| CSVのまま継続 | **不採用** | 必要な成果物形式と一致しない |

## 検討事項
JSON Schema、エラー時の出力形式、JSON妥当性検証、最大サイズ、S3保持期限は詳細設計で決める。**Bedrockのトークン消費後に結果生成・保存・取得が失敗した場合の請求可否は引き続き未決定。**

## 経緯
2026-10-14: 成果物がCSVではなくJSONになることを確認。同期化やS3不要化も一時検討したが、利用者の指定により**非同期・S3保存・ポーリングを変更せず、出力形式のみJSONに変更**すると決定。

## 2026-10-19後続の検討

Web Functionsを採用しても、非同期で生成されたJSONの永続保管のためS3を引き続き使用する。SQSをWorker前段に追加する案は[ADR-0009](0009_SQS公平キュー導入検討.md)で検討。元の直接非同期InvokeはSQS追加前の採用履歴。
